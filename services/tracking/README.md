# `services/tracking/`

Centralized PostHog wrapper for the EduQuest FastAPI backend. Generated by the
`product-tracking-implement-tracking` skill from `.telemetry/tracking-plan.yaml` v1
and `.telemetry/instrument.md`.

## Files

| File | Purpose |
|---|---|
| `events.py` | `Events` class — single source of truth for backend event names. |
| `posthog_client.py` | Singleton `Posthog` client. Falls back to a null client when `POSTHOG_API_KEY` is unset (so tests don't need it). |
| `track.py` | `track_event`, `identify_user`, `group_identify_period`. PII guard + internal-user guard + auto `period` group attachment. |
| `examples.py` | Reference patterns; not imported at runtime. |

## Setup

1. Install:
   ```bash
   echo "posthog>=4.0.0" >> requirements.txt
   pip install -r requirements.txt
   ```
2. Set env:
   ```bash
   POSTHOG_API_KEY=phc_xxx
   POSTHOG_HOST=https://us.i.posthog.com
   ```
3. Wire shutdown into FastAPI lifespan (in `main.py`):
   ```python
   from contextlib import asynccontextmanager
   from services.tracking import shutdown_posthog

   @asynccontextmanager
   async def lifespan(_app):
       yield
       shutdown_posthog()

   app = FastAPI(lifespan=lifespan, ...)
   ```

## Usage

```python
from services.tracking import Events, track_event

track_event(
    user_id=quest.user_id,                   # NEVER email
    event=Events.QUEST_GRADED,
    properties={
        "quest_id": quest.quest_id,
        "period_id": quest.period_id,        # auto-attaches groups={"period": ...}
        "week": quest.week,
        "graded_by": "ai",
        "overall_score_band": "80_to_89",
        "skill_mastery_count": 3,
        "skill_total_count": 4,
    },
)
```

## Hard rules

- **Never call `posthog.capture` directly.** Use `track_event(...)`.
- **`user_id` is required and must be the canonical Supabase user_id.** Email is a trait, not an identifier.
- **No free-text in event properties.** `goal_text`, `course_name`, file names, chat content, quest answers, feedback text — all stripped at the wrapper.
- **Period-scoped events** must include `period_id` in `properties` — the wrapper attaches `groups={"period": period_id}` automatically.
- **Errors do not raise.** Every `track_event` failure is logged at WARN; the request handler continues.

## Where to fire each event

See `.telemetry/delta.md` "Migration plan" for the full hook map. Quick reference:

| Event | Fire from |
|---|---|
| `quest_graded` | `services/quest/quest_grading_service.py` after `bots/grading_agent` returns |
| `quests_generated` | `services/quest/quest_creation_service.py` after agent run |
| `schedule_generated` | `services/period/period_schedule_service.py` after agent run |
| `skill_mastery_updated` | wherever the boolean recompute happens (post-grading) |
| `student_period_joined` | `services/enrollment/enrollment_service.py::verify_and_enroll` |
| `parent_invite_sent` | `services/parent/parent_service.py::generate_invite` |
| `parent_invite_accepted` | `services/parent/parent_service.py::accept_invite` |
| `period_files_uploaded` | `services/period/period_file_helpers.py` after S3 + vector store update |
| `pilot_waitlist_approved` | `services/waitlist/waitlist_service.py::approve` (or admin endpoint) |
| `user_signup_failed` / `user_login_failed` | `services/auth/auth_service.py` failure paths |
| `password_reset_requested` / `password_reset_completed` | move from Next API routes → `services/auth/password_reset_service.py` and identify the user_id (no more `"anonymous"`) |

## Verifying

1. With `POSTHOG_API_KEY` unset, the wrapper installs a null client — no traffic, no errors.
2. With a valid key, hit a route → check PostHog UI → Activity → Live Events.
3. `groups.period` attribution shows on PostHog UI → Groups → period.

## Regenerating

After updating `.telemetry/tracking-plan.yaml`, re-run the
`product-tracking-implement-tracking` skill to refresh `events.py` and update
`track.py` for new shapes.
